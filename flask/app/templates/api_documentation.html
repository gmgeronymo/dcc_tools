Introdução

API DCC Tools

DCC Generator

A API recebe como entrada uma string em formato JSON, que deve ser enviada via uma requisição POST

Endpoint da API: https://sig-dimci.inmetro.gov.br/dcc/generate

Versão de schema suportada: 3.3.0. O campo dcc_version aceita apenas 3.3.0; se omitido, o padrão é 3.3.0. Requisições com 3.2.0 retornam erro 400.

Exemplo de arquivo JSON:
{ "chave1": "valor", "chave2": "valor", "chave3": [ { "subchave1": "valor", "subchave2": "valor" } ], "chave4": "valor" }

Autenticação

As funções de geração e upload exigem uma API-KEY de usuário, enviada no cabeçalho HTTP X-API-Key. Requisições sem chave, com chave inválida ou revogada recebem 401.

Transição para clientes antigos: clientes de API que ainda não enviam a API-KEY recebem uma resposta XML (<autenticacaoNecessaria>, status 401) com o aviso de cadastro, o endereço de /dcc/register e instruções para incluir o cabeçalho X-API-Key. Navegadores são redirecionados para /dcc/login.

Cadastro de usuário (auto-cadastro):

POST /dcc/register

{ "username": "nome_usuario", "email": "opcional@exemplo.com", "password": "senha_com_no_minimo_8_caracteres" }

Resposta 201:

{ "username": "nome_usuario", "email": "opcional@exemplo.com", "api_key": "dcc_...", "created_at": "2026-09-18T12:00:00+00:00" }

A password é obrigatória (mínimo de 8 caracteres) e armazenada com hash. A api_key é gerada automaticamente e também pode ser consultada na área de perfil.

Exemplo de chamada:
POST /dcc/generate X-API-Key: dcc_... Content-Type: application/json
Interface web:

O login é feito em /dcc/login com usuário e senha e cria uma sessão; a autorização das funções é transparente (não é preciso informar a API-KEY). Na área de perfil (/dcc/perfil) o usuário consulta a sua API-KEY e pode gerar uma nova. As páginas informativas e as ferramentas de visualizar DCC (/dcc/upload_xml_hr) e validar XML (/dcc/validate_xml) permanecem abertas; as funções de geração e upload de JSON/Excel e a anexação em PDF exigem login. Ao tentar acessar uma função protegida sem estar autenticado, a aplicação avisa que a autenticação é necessária e indica login e cadastro.

Declarações Fixas

O sistema gera automaticamente três declarações fixas no certificado. Estas não precisam ser informadas na entrada, mas seus textos são incluídos no XML DCC:

Declaração Origem Descrição
cmc Gerada automaticamente Declaração sobre a Conformidade com as Capacidades de Medição e Calibração (CMCs) do MRA do BIPM. Incluída apenas quando cmc = true.
norma Gerada automaticamente Declaração de conformidade com a norma ABNT NBR ISO/IEC 17025. Incluída em todos os certificados.
requisitos Gerada automaticamente Declaração sobre a validade e restrições de uso do certificado. Incluída em todos os certificados.

Graus de liberdade efetivos (nueff): campo opcional. Quando presente, a API gera uma dcc:quantity adicional na mesma dcc:list de resultados, nomeada Graus de liberdade efetivos, com os valores em dcc:charsXMLList (representação textual, sem unidade). O número de valores de nueff deve ser igual ao número de resultados do mensurando associado. Valores 0, negativos, -inf, null, vazios, NaN ou não numéricos são rejeitados; o infinito positivo pode ser informado como "inf" e é representado como inf no XML. Se omitido, o certificado é gerado sem a quantidade adicional, preservando o comportamento anterior.

Marcação de pontos dentro/fora da CMC (in_cmc)

O DCC 3.3.0 não possui campo nativo de CMC. A API implementa o mecanismo basic_isInCMC (DKD-E 7-2, §4.5): o dcc:statement de CMC já emitido quando cmc=true é adaptado com id e refType="basic_isInCMC" em administrativeData/statements, sem criar um segundo statement. Cada dcc:quantity de resultado é vinculada por dcc:measurementMetaData/dcc:metaData[@refId], usando dcc:valid (ponto único) ou dcc:validXMLList (um booleano por ponto, na ordem de si:valueXMLList).

  • in_cmc por resultado: true = ponto coberto pela CMC; false = fora.
  • cmc_padrao: valor aplicado aos resultados sem in_cmc. Ausente = false.
  • Os vínculos por ponto são gerados se houver ao menos um in_cmc ou se cmc_padrao for informado. O statement de CMC é emitido quando cmc=true ou quando há marcação.
  • Para indicar somente as exceções, use "cmc_padrao": true e "in_cmc": false nos pontos fora da CMC.
  • cmc_declaracao personaliza id, nome, referencia, link, descricao e autoridade.
  • O namespace basic é declarado automaticamente em refTypeDefinitions quando o statement de CMC é emitido.
Exemplo
"cmc": true, "cmc_padrao": true, "resultados": [ { "mensurando": "acdc", "value": "10.001", "unc": "0.002", "k": "2", "in_cmc": true }, { "mensurando": "acdc", "value": "20.002", "unc": "0.003", "k": "2", "in_cmc": true }, { "mensurando": "acdc", "value": "30.003", "unc": "0.004", "k": "2", "in_cmc": false } ]
XML gerado (trecho)
<dcc:statement id="inCMC" refType="basic_isInCMC"> <dcc:name><dcc:content lang="pt">CIPM-MRA</dcc:content></dcc:name> <dcc:description><dcc:content lang="pt">Todos os resultados são acompanhados por um elemento dcc:valid ...</dcc:content></dcc:description> <dcc:reference>CIPM-MRA — Apêndice C / KCDB</dcc:reference> <dcc:link>https://www.bipm.org/kcdb/</dcc:link> <dcc:declaration><dcc:content lang="pt">Este certificado é consistente com as CMCs...</dcc:content></dcc:declaration> <dcc:respAuthority> <dcc:name><dcc:content lang="pt">BIPM</dcc:content></dcc:name> <dcc:location><dcc:city>Paris</dcc:city><dcc:countryCode>FR</dcc:countryCode></dcc:location> </dcc:respAuthority> </dcc:statement> <dcc:quantity refType="basic_measuredValue"> <dcc:name><dcc:content lang="pt">\delta_u</dcc:content></dcc:name> <si:realListXMLList>...</si:realListXMLList> <dcc:measurementMetaData> <dcc:metaData refId="inCMC"> <dcc:validXMLList>true true false</dcc:validXMLList> </dcc:metaData> </dcc:measurementMetaData> </dcc:quantity>

Critério metrológico: marque true somente quando (a) o valor estiver dentro da faixa coberta pela CMC aplicável e (b) a incerteza declarada for maior ou igual à incerteza da CMC, comparadas na mesma base estatística (mesmo k ou ambas convertidas para incerteza padrão). Não use dcc:conformity para indicar CMC. Referência: DKD-E 7-2, §4.5, e vocabulário de refType do DKD/PTB.

Na visualização: em POST /dcc/visualizar_dcc, as tabelas de resultados com measurementMetaData exibem a coluna CMC (Sim/Não) alinhada aos pontos. Se houver pontos false, a seção Observações recebe uma observação numerada, após as observações do certificado, informando que esses pontos não estão cobertos pela CMC, embora a rastreabilidade esteja garantida da mesma forma que sustenta a dos demais pontos. Certificados sem marcação não exibem a coluna nem a observação. Valores inf (por exemplo, em nueff) são exibidos como ∞.

Valor Nominal do Item

O DCC 3.3.0 permite registrar quantidades do item em administrativeData/items/item/itemQuantities/itemQuantity. Seguindo o DKD-E 1-1, o valor nominal (valor de placa/impresso) é declarado com refType="basic_nominalValue".

Formato recomendado
"valor_nominal": { "valor": "100", "unidade": "\\kilo\\ohm", "nome": "Valor nominal", "descricao": "Valor impresso no item" }
Campo Tipo Obrigatório Descrição
valor string/número Obrigatório Valor nominal.
unidade string Obrigatório Unidade D-SI (ex.: \\ohm).
nome string Opcional Rótulo do itemQuantity; padrão Valor nominal.
descricao string Opcional Descrição adicional.
Formato legado (compatibilidade)
"valor_nominal": "100", "valnom_unit": "\\kilo\\ohm"
XML gerado (trecho)
<dcc:item> <!-- ... --> <dcc:identifications>...</dcc:identifications> <dcc:itemQuantities> <dcc:itemQuantity refType="basic_nominalValue"> <dcc:name><dcc:content lang="pt">Valor nominal</dcc:content></dcc:name> <dcc:description><dcc:content lang="pt">Valor impresso no item</dcc:content></dcc:description> <si:real> <si:value>100</si:value> <si:unit>\kilo\ohm</si:unit> </si:real> </dcc:itemQuantity> </dcc:itemQuantities> </dcc:item>
  • Campo opcional; sem ele não há itemQuantities.
  • O namespace basic é declarado automaticamente em refTypeDefinitions quando o valor nominal (ou a marcação CMC) é emitido.
  • A visualização exibe o valor em Características do Item como Valor nominal: 100 kΩ.
  • O valor nominal não recebe incerteza de medição; ele documenta o valor de placa/impresso.
  • Referência: DKD-E 1-1 (Normalwiderstände), seção 3.4.
